# SEPA 트렌드템플릿 일일 스캐너

Mark Minervini의 SEPA 1단계(Trend Template 8조건)를 한국·미국 전 종목에 매일 자동 적용하고 PDF 리포트를 생성합니다.

## 설치

```bash
pip install -r requirements.txt

# DART API 키 발급(무료): https://opendart.fss.or.kr
export DART_API_KEY="발급받은40자리키"
```

## 실행

```bash
python run_daily.py     # 1단계 스캔 → 2단계 DART 검증 → PDF 리포트

# 개별 실행
python sepa_scanner.py --market KR              # 한국만
python sepa_scanner.py --market US --min-rs 80  # 미국만, RS 80 이상
python dart_fundamentals.py --tickers 005930,000660,034020   # 특정 종목 재무만 확인
python dart_fundamentals.py --from-scan output/sepa_scan_20260820.csv
python make_report.py --csv output/sepa_scan_20260820.csv
```

DART_API_KEY가 없으면 2단계는 자동으로 건너뛰고 1단계 결과만 리포트에 담깁니다.

## 매일 자동 실행 (cron)

```bash
crontab -e
# 한국 장 마감 후 평일 18:30
30 18 * * 1-5 cd /path/to/sepa && /usr/bin/python3 run_daily.py >> run.log 2>&1
```

`sepa_scanner.py` 상단 파라미터 블록에서 전부 조정 가능합니다.

## 2단계: DART 펀더멘털 (한국)

`dart_fundamentals.py` — OpenDART '다중회사 주요계정'(fnlttMultiAcnt) API 사용.

기본 조건 (`dart_fundamentals.py` 상단에서 조정):

| 항목 | 기본값 |
|---|---|
| 최근 분기 순이익 YoY | +25% 이상 |
| 최근 분기 매출 YoY | +20% 이상 |
| 이익 증가율 가속 | 계산은 하되 필수 아님 (`REQUIRE_ACCEL=True`로 강제 가능) |

**분기 실적 산출 방식**: DART가 주는 `thstrm_amount`는 회사마다 3개월/누적 표기가
달라 신뢰도가 낮습니다. 그래서 누적금액을 받아 직접 차분합니다:

```
Q1 = 1분기 누적
Q2 = 반기 누적 - Q1 누적
Q3 = 3분기 누적 - 반기 누적
Q4 = 연간 - 3분기 누적
```

직전 분기가 미공시면 NaN 처리해 잘못된 값이 흘러들지 않게 했습니다.

**API 호출량**: 회사 100개씩 묶어 3년 × 4분기 = 12회 호출. 1단계 통과 종목이
50개라면 하루 12회면 끝나므로 일일 한도 20,000건에 한참 못 미칩니다.

### 2단계의 알려진 한계

- **EPS가 아니라 순이익 증가율입니다.** 주요계정 API에 EPS 항목이 없어 대용치로 씁니다.
  유상증자·무상증자가 있었던 종목은 실제 EPS 증가율과 괴리가 생깁니다.
  정확한 EPS가 필요하면 `fnlttSinglAcntAll`(전체계정)에서 주당순이익을 뽑거나
  pykrx의 상장주식수로 나눠 보정해야 합니다.
- **금융업 제외**: 은행·보험·증권은 주요계정 API 대상이 아니라 조회되지 않습니다.
- **적자 기업은 NaN**: 전년 동기가 적자면 증가율 계산이 불가능해 자동 탈락합니다.
  적자 축소나 흑자 전환 종목을 잡고 싶다면 별도 로직이 필요합니다.
- **공시 지연**: 분기보고서는 분기 종료 후 45일 이내 제출이라, 최근 분기 데이터가
  아직 안 올라와 있을 수 있습니다.

## RS Rating에 대하여

IBD의 RS Rating은 유료 독점 지표라 API로 받을 수 없습니다. 공개된 표준 근사식으로 대체했습니다:

```
RS Score = 2×(3개월 수익률) + (6개월) + (9개월) + (12개월)
→ 유니버스 내 백분위를 1~99로 환산
```

주의: 백분위는 **유니버스 상대값**입니다. 미국은 S&P500만 스캔하면 "S&P500 내 상위 %"가 되므로,
IBD처럼 전체 시장 기준으로 쓰려면 `us_universe()`를 러셀3000 등으로 확장해야 합니다.

## 알려진 제약

- **yfinance는 비공식 라이브러리**입니다. 야후가 2017년 공식 API를 중단한 뒤 웹 엔드포인트를
  스크래핑하는 방식이라 레이트 리밋·IP 차단·예고 없는 스키마 변경 위험이 있습니다.
  매일 돌리는 운영 시스템이라면 EODHD(벌크 다운로드 지원) 등 유료 소스로 교체를 권장합니다.
  교체 시 `fetch_us()` 함수 하나만 수정하면 나머지 로직은 그대로 재사용됩니다.
- **pykrx 첫 실행은 오래 걸립니다.** 약 280 영업일 × 2개 시장 = 560회 호출, 대략 10~20분.
  이후 `cache/` 에 parquet으로 저장되어 재실행은 빠릅니다. 서버 차단 방지를 위해 호출당 0.12초
  대기를 넣어두었으니 이 값을 줄이지 마세요.
- **자동화된 것은 SEPA 1단계뿐입니다.** 2단계 펀더멘털(EPS·매출 성장률, 기관 수급)과
  3단계 정밀 진입(VCP, 피벗포인트 돌파, 거래량 확인)은 통과 종목을 대상으로 직접 확인해야 합니다.
- **수정주가 처리**: 미국은 `auto_adjust=True`로 배당·분할 반영. 한국 pykrx 종가는 액면분할이
  소급 반영되지 않을 수 있어, 분할 직후 종목에서 이동평균이 왜곡될 수 있습니다.

## 대시보드 신규 기능 (날짜 조회 · 매매전략 · 시장상태)

### 날짜별 조회
`history/` 폴더에 날짜별 대시보드가 영구 보관됩니다. GitHub Actions는 이 폴더를
**저장소에 직접 커밋**합니다(예전엔 Actions 캐시를 썼는데, 캐시는 만료되거나
초기화될 수 있어 날짜 조회가 끊기는 원인이 됐습니다). 화면 우측 상단 날짜
드롭다운에서 과거 날짜를 선택하면 그날의 대시보드로 이동합니다.

### 시장 상태 배너
화면 상단에 그날 한국·미국 시장이 정규장/휴장/조기폐장 중 무엇인지 표시됩니다.
`market_calendar.py`에 2026년 휴장일이 정적 테이블로 들어있습니다(설날, 추석,
제헌절, 추수감사절 등). **매년 초 다음 해 테이블을 추가해야 합니다.**
휴장인 시장은 그날 데이터 자체가 화면에서 숨겨집니다.

### 매매전략 탭
"매매전략" 버튼을 누르면 그날 스캔 데이터를 SEPA 규칙에 대입한 전략이 뜹니다.
포함 내용: 시장 국면(스캔 통과율 기반), 포지션 사이징 가이드, 신규 진입
체크리스트, 보유·청산 기준, RS 90 이상 진입 후 경과 거래일(D, D+1, D+2…) 표.

**한계**: 실시간 뉴스나 매크로 지표를 그 순간 조회해 요약하는 것이 아니라,
스캔 통계(통과종목 수, RS 분포)를 규칙에 대입해 생성하는 정적 서술입니다.
화면 하단 고지문에도 명시되어 있습니다.

### RS90 진입일 레지스트리
`history/rs90_registry.json`에 종목별 RS90 최초 진입일이 누적됩니다. 도중에
RS가 90 밑으로 떨어지면 기록이 지워지고, 다시 90을 넘으면 그날이 새 진입일이
됩니다. 휴장일에는 그 시장 기록을 건드리지 않습니다.
